# Reproduction

Les outils et méthodes disponibles pour la reproduction sont listés dans `remake-tools.md`. Chaque outil a sa propre documentation sur son utilisation, son coût et la manière d'aider l'utilisateur à l'intégrer : `chatcut.md`, `capsule-cinema.md`, `diy.md`.

## Suivre les instructions

Le rapport « Reproduction DIY » commence par identifier le type de vidéo (15 catégories telles que face caméra, prise de vue sur table, courte vidéo IA, montage rythmé, etc., déterminées par la proportion des catégories d'images, le format de tournage réel, le type de son et le rythme de montage), puis liste les étapes de production dans l'ordre pour ce type de vidéo. Chaque étape ne décrit que les données mesurées sur la vidéo originale (cadrage, éclairage, rythme de montage, style des sous-titres, source audio, unité de génération) et les fichiers et commandes de cet outil. Les données non mesurées ne sont pas incluses. Cette section est présentée à l'utilisateur pour qu'il la réalise lui-même ; si le type est mal identifié, il doit le signaler et suivre l'ordre du type correct. N'ajoutez pas de chiffres empiriques autres que les mesures.

## Exécuter une commande d'abord

`rea-video remake out/ref` : les images fixes sont reconstruites selon le mouvement mesuré (les plans rendus par code utilisent par défaut le plan original comme placeholder, il est recommandé de les refaire avec un framework vidéo HTML ; ajoutez `--code` pour exécuter automatiquement `code-remake` et obtenir un brouillon rapide), les plans de `remake/results.json` (généré par `remake-run`) et `remake/mine.json` (fourni par l'utilisateur ou généré manuellement sur la page web, format `{"results": {"numéro_de_plan": {"video": "chemin_absolu"}}}`) sont montés, le reste est remplacé par le plan original, assemblé selon la timeline originale, et les sous-titres sont superposés. `remake/status.md` décrit plan par plan ce qui a été fait et ce qui reste à faire. Chaque fois qu'un nouveau plan est obtenu, il est écrit dans `mine.json` et la commande est exécutée à nouveau. Les sections suivantes détaillent chaque type de plan.

## Quel modèle utiliser

- Le modèle, la reproduction de l'ensemble ou seulement des plans IA, et les remplacements sont tous spécifiés dans `remake/intent.yaml` (voir SKILL.md « Reproduction »). `rea-video plan out/ref` génère un plan basé sur ce fichier. Si l'utilisateur n'a pas spécifié de modèle, un plan est généré avec le modèle par défaut (MiniMax H3, ou le modèle mémorisé par `prefs engine`) et cela est précisé dans la réponse, sans demander de précisions ; si l'utilisateur souhaite changer de modèle, il peut exécuter `rea-video plan out/ref --model <id>`.
- Les prompts pour chaque unité dans le rapport sont des brouillons. Écrivez la version finale dans `remake/prompts.json` en suivant le format imprimé par `rea-video models <id>` : comment diviser le temps et les plans, comment référencer les matériaux de référence, comment écrire les dialogues et le contenu indésirable ; en mode image clé / images de début et de fin, ne conservez que le mouvement et le mouvement de caméra. `rea-video plan` vérifiera le respect des règles de format de ce modèle.
- Comment sélectionner les images, effacer le texte, et associer les images de début et de fin : `rea-video models keyframes`.

## Comment reproduire les différents types de plans

- **Plans de type IA** (les plans filmés sont également inclus lorsque `generate: all`) : les plans consécutifs doivent être inclus dans la même génération si possible. Le mode d'entrée est choisi en fonction de ce que le modèle peut traiter : si le modèle peut traiter des vidéos de référence, la section originale est nettoyée des sous-titres et utilisée comme `@vidéo1`, et le modèle génère en fonction de son storyboard et de son rythme ; si le modèle ne peut pas traiter des vidéos de référence mais peut gérer plusieurs plans et plusieurs images à la fois, une image de la vidéo originale est fournie pour chaque plan afin de définir la composition ; si aucune de ces options n'est possible, les images de début et de fin sont utilisées plan par plan. Les éléments à remplacer sont écrits selon les images et les descriptions de l'intention ; si certains éléments ne sont décrits que par du texte, chaque décomposition supplémentaire augmente la probabilité d'obtenir un résultat différent, il est donc préférable de générer en une seule fois. Pour les plans où le nombre d'images est insuffisant, la composition est écrite dans le prompt, et ce n'est que si des images de référence sont fournies que la décomposition sera plus détaillée en fonction du nombre d'images. Cela peut être exécuté automatiquement via capsule-cinema (des frais seront facturés, utilisez d'abord `--dry-run` et obtenez le consentement de l'utilisateur ; voir `capsule-cinema.md`).
- **Pan/zoom sur images statiques, images fixes** : reconstruction locale selon les paramètres de mouvement mesurés.
- **Rendu par code** : refaire avec un framework vidéo HTML (comme HyperFrames, voir `hyperframes.md`) : les points de coupe, les transitions et les images clés de chaque plan selon `video/rhythm.md`, la mise en page, les couleurs et les éléments selon le rapport « Composition par code ». `code-remake` n'est qu'un brouillon rapide ; les graphiques à fond sombre comme les particules, les nuages de points et les visualisations de données peuvent être proches de la vidéo originale, mais les mouvements et les déformations des personnages illustrés ne peuvent pas être reproduits. Pour un brouillon, exécutez `rea-video code-remake out/ref`. Il utilise les points d'échantillonnage ou les découpes de chaque scène dans le package de décomposition `frames/`, ainsi que le mouvement et la lumière de fond mesurés, pour écrire `out/ref/code/` (avec `spec.json` pour chaque scène, `render.py` pour le moteur de rendu, `overlays.ass` pour le texte), aligne la quantité et la luminosité de chaque scène avec la vidéo originale, rend `code/remake.mp4`, puis compare avec la vidéo originale.
  - Les modifications ultérieures commencent à partir de cette version : modifiez d'abord les nombres dans `spec.json` (nombre de particules `count`, taille `dot`, luminosité `gain`, mouvement `motion`, lumière de fond `glow`) ; pour changer en une nouvelle forme, remplacez `points` par votre propre fichier de points ; pour créer des effets non présents dans la vidéo originale, modifiez `render.py`, ou réécrivez-le en Remotion / Three.js. Après modification, réexécutez la même commande, le `spec.json` modifié sera conservé, `--reset` reconstruira à partir de zéro. `python code/render.py --frame 12.5` peut générer une seule image pour la visualisation.
  - Modifiez selon l'`advice` de `lowest_scenes` dans la sortie, en commençant par la scène avec le score le plus bas, en vous référant à `code/compare/compare_worst.jpg`.
  - La description de l'image de chaque plan dans la section « Composition par code » du rapport, les captures d'écran des éléments dans `shots/` et les barres d'images clés sont utilisées pour compléter ce que l'outil ne peut pas mesurer : comment les annotations apparaissent, et la signification des graphiques.
- **Plans de danse / action** (marqués par `performance.move` lors de la visualisation des images) : ne pas utiliser les images de début et de fin. Le rapport « Pilotage d'action » décrit l'approche et les prompts : par défaut, la vidéo originale est directement utilisée comme vidéo de référence ; ce n'est que si l'arrière-plan original est encombré ou si la nouvelle scène est très différente que l'on passe à la profondeur et aux modèles blancs ; si l'expression doit être reproduite, restez en référence directe (la profondeur et les modèles blancs perdent les expressions). Exécutez d'abord `rea-video drive out/ref` pour obtenir la vidéo de pilotage sans sous-titres et découpée selon les pauses (le `drive/README.md` contient la situation de chaque segment), vérifiez d'abord `drive/segments.jpg` pour voir si les mains et les pieds sont mal effacés ; écrivez les segments générés dans `drive/results.json` puis `rea-video drive out/ref --join`, puis `rea-video remake`.
- **Matériel réel** : listez les éléments à fournir par l'utilisateur ; une fois reçus, écrivez-les dans `remake/mine.json` et exécutez `rea-video remake`, ou mettez-les dans ChatCut pour les monter selon le rythme de la vidéo originale.
- **Performance et émotion** : la section « Performance et émotion » du rapport décrit plan par plan les émotions, expressions, actions et tons. Les prompts des unités de génération incluent déjà les expressions et actions. Lors de la réécriture des prompts, conservez les expressions et actions visibles, ne les remplacez pas par des mots comme « heureux » ou « triste », et n'exagérez pas l'amplitude ; pour les plans avec dialogue, faites d'abord le doublage avec le ton, puis laissez l'image suivre le son.
- **Son** : trois pistes sont préparées séparément : TTS (selon le ton de chaque phrase dans le script), BGM (selon le BPM / la tonalité / l'émotion), et effets sonores (selon les points temporels).
- **Habillage de montage (sous-titres, texte stylisé, stickers)** : non inclus dans la génération. Le modèle de génération ne produit que des personnes et des images propres, la couche d'habillage est superposée à la fin selon la timeline de la « Couche d'habillage de montage », de sorte que le texte ne soit pas flou par le modèle, et que le changement de texte ne modifie que la couche d'habillage.
  - Les références tirées de la vidéo originale (vidéo de référence, images clés, images de début et de fin) se trouvent dans `remake/refs/`, les sous-titres, le texte stylisé et le texte permanent ont été effacés.
  - Lors du changement de texte, le texte stylisé et les stickers sont placés sur les phrases correspondantes du nouveau texte selon le « Positionnement par dialogue » du rapport, sans réutiliser les secondes originales ; les « Calques permanents » sont superposés une fois sur toute la section.

Pour savoir comment assembler les matériaux filmés par l'utilisateur ou les vidéos générées manuellement sur la page web dans la timeline originale, voir `diy.md` ; pour la génération automatique avec capsule-cinema, voir `capsule-cinema.md`.
